**`context_for_task` seed-quality gate + identifier-aware OR fallback (loop-substrate PR-6).** Task-mode responses now stamp `_meta.seed_quality` (`level` high/medium/low, `exact_name_match`, `name_match_ratio`, `identifier_tokens`, `seeded_via`). When BM25 matched seeds only via text the caller never said (docstrings, signatures) — i.e. no seed *name* shares an identifier token with the task — the response degrades to `mode:"suggestions_only"`: seed metadata plus recovery `next_steps` (~300 tokens) instead of a full, likely wrong-cluster, multi-thousand-token expansion. `expand=true` overrides the gate; `seed_id` mode is exempt (the caller named their anchor). The #1440 AND→OR fallback now ORs only identifier-shaped + non-stopword tokens instead of every prose word, cutting the noise that prose filler ("the", "make", "missing") pulled in. Motivated by a measured dogfood mis-seed: a prose task expanded a 5.6k-token envelope around an unrelated symbol cluster at `tokens_saved: 0`.
