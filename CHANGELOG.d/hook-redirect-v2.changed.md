**Budgeted Read redirects + honest hook savings measurement (hook-redirect-v2).** The PreToolUse hook's Read→`context lite=true` advisory now carries a `max_tokens` budget derived from the intercepted Read call's own `limit` param (limit × ~12 tokens/line, floor 400; Read's implicit 2000-line page when no limit) — a redirected giant file can no longer blow the window harder than the Read it replaced. `context` grew matching lite-mode plumbing: `max_tokens` truncates source at the budget with an explicit marker + `truncated:true` flag (never silent). A Read with `limit` set (but no `offset`) now redirects instead of passing through, since the budget honors the narrowing. Repeat-read awareness: when the same file was already served this session and its content hash is unchanged, the hint adds one line telling the agent a re-read returns identical bytes. Measurement: schema v40 adds `hook_invocations.est_tokens_served` + `baseline_tokens` (estimated cost of the suggested lite call vs the stat-ed size of what the Read would actually have returned, capped by its limit) — the honest "savings vs realistic baseline" number, surfaced in `/v1/hook-stats`, `pincher hook-stats --export-7d` (additive `savings` block), and a new HOOK 7D section in `pincher stats`. Grep interception was analyzed and deliberately NOT built — see `docs/methodology/grep-interception.md` for the design sketch and the fundamental blocker (FTS indexes no body text).
