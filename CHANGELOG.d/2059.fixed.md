**MCP transport interop hardening: bare HTTP tool paths now resolve, and the stdio diagnostic path documents server requests ([#2059](https://github.com/kwad77/pincher/issues/2059)).** HTTP callers can now `POST /search` as a compatibility alias for the documented `POST /v1/search` tool route; the dispatcher normalizes the leading slash before tool lookup, so generic adapters that map a tool name directly into the URL path no longer see `unknown tool "/search"`. The stdio side was confirmed to be the MCP roots handshake, not a duplicate initialize response: pincher sends a server-to-client `roots/list` request after initialize, and clients must answer id-bearing server requests before `tools/call` can complete. Pincher's `health-check` probe already does that; the regression coverage now pins the HTTP alias and keeps the diagnostic shape explicit for future transport work.
