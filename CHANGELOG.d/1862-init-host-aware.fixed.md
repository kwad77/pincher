`pincher init` no longer silently defaults to `--target=claude` ([#1862](https://github.com/kwad77/pincher/issues/1862)). Running it inside a non-Claude host (e.g. Codex) used to write a `CLAUDE.md` + `.claude/` PreToolUse hook the user never asked for. With no explicit `--target`, init now resolves the host: the agent pincher is running under (env signal — `CLAUDECODE` ⇒ Claude Code), then editor marker files. When the host can't be auto-detected and init is running interactively, it shows a picker (the common agents plus an "other" entry for the full list); a scripted run with no TTY gets a clear refusal with the `--target` list rather than a wrong guess. The MCP `init` tool gets the same host-aware treatment — an empty `target` no longer falls through `detect` to the claude fallback. Explicit `--target=X` is unchanged.
