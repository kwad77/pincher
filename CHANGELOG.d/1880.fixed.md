**`investigate_failure` now filters Go testing-package output vocabulary from ranked suspects (#1880).** Tokens emitted by every Go test failure (`--- FAIL: TestX` / `--- PASS:` / `=== RUN` / `=== PAUSE` / `FAIL\t<pkg>\t<seconds>s` / `exit status N`) were being treated as identifier-shaped frame tokens and BM25-matching unrelated symbols whose names happen to be common English verbs — `compare` matched `cmd/benchcmp.compare` (from "fetching origin to compare..."), `fetch` matched `install.sh::install.fetch` (from "git fetch"), `FAIL` matched `scoop-manifest_test.fail`. The fix adds `FAIL` / `PASS` / `SKIP` / `RUN` / `PAUSE` / `status` / `exit` to `stopwordFrames` — the same treatment Go runtime panic vocabulary got in #1787. Common-verb tokens (`compare` / `fetch` / `check` / `update`) are intentionally NOT filtered since a real failure site could legitimately bear those names. Regression test `TestInvestigateFailure_TestFrameworkVocabularyFiltered_1880` pins the new stopwords + asserts real identifier-shaped tokens (`TestX`, `TestY`) still survive.
