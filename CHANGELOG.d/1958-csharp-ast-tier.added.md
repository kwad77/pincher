**C# extraction promoted to AST tier (1.0) via real tree-sitter ([#1958](https://github.com/kwad77/pincher/issues/1958), ADR-0008).** C# `.cs` files now extract through real upstream tree-sitter compiled to WASM (`wazero`, pure-Go / `CGO_ENABLED=0`) — the third non-Go/Py/JS language at AST tier, after Rust (#1957) and Java. Same per-file all-or-nothing dispatcher: a clean parse (`HasError()==false`) yields AST-exact symbols at confidence **1.0**; a parse error or `PINCHER_DISABLE_CSHARP_AST=1` falls back to the regex tier (0.85). QNs are **namespace-blind** (keyed on `moduleQN`, matching the regex tier) so symbol IDs stay stable; the extractor correctly handles C#'s bare-identifier return types (picks the method name, not the return type), constructors, generic methods, `record`/`struct`→Class, and adds `using`-directive IMPORTS the regex tier never captured. Validated by an inline unit test, a no-leak-under-3000-reuses RSS test, and a marshaler fuzz target. Measured on Newtonsoft.Json (945 files): **92.8% parse cleanly → AST tier**; the remaining 7.2% (preprocessor `#if/#else/#endif`-heavy and some attribute edge cases — a tree-sitter-c-sharp grammar limitation) gracefully fall back to the regex tier, so the change is **never worse than before**. **Cost:** binary +~6 MB — the C# grammar is a size outlier (`parser.c` ~34 MB → WASM 1.6→7.5 MB, binary ~41→47 MB); a grammar update for better preprocessor handling is tracked as follow-up. **Breaking note:** re-indexing a C# project changes some symbol IDs where tree-sitter scopes more precisely (nested types, constructors, no false-positive `new Xxx()` methods) than the old regex tier — announced, not silent.
