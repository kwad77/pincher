**Envelope compression — session-delta `_meta`, `format=text`, ditto hops.** Three low-risk token-compression features; each preserves the information the consumer needs in fewer agent-context tokens. (1) **Session-delta `_meta`** (every call benefits): `_meta.capabilities` is a per-server constant, so only the FIRST success response of a session carries it — subsequent responses omit the array and stamp `_meta.meta_delta: true` so omission reads as intent, not accident. Measured saving: **~74 tokens/call** (294-byte capabilities field) on every post-first response. The array is re-emitted in full whenever the capability set actually changes (e.g. streamable-HTTP enabled mid-process); per-tool fields (`complexity_tier`, `baseline_method`) and error envelopes are never delta'd; `PINCHER_META_CAPABILITIES=off` (#1087) still wins. Kill-switch: `PINCHER_META_DELTA=0` restores legacy every-call emission. (2) **`format="text"` on `search` and `trace`**: renders the list-shaped payload as a dense TSV block (`data.results_text`, replacing the `results`/`hops` array) inside the standard envelope — header row once, then `id<TAB>kind<TAB>file:line<TAB>signature-or-name` per search hit / `depth<TAB>risk<TAB>id` per trace hop. `_meta` and the pagination envelope are unchanged; unknown format values warn and fall back to json. Measured on a representative 20-hit search: **1107 vs 2445 tokens — ratio 0.45** (gate-tested < 0.7). (3) **Ditto compression in trace hops**, gated behind the existing `compact=true` flag (default shape untouched — zero compat risk): consecutive nodes within a depth block sharing a `file_path` omit the repeated field; the first occurrence carries it. Deterministic and locally decodable — scan up to the nearest node carrying `file_path`. Measured on a 4-hop hub trace with short paths: **78 vs 87 tokens (~10%; grows with path length and hub fan-in)**.
