**`mode=skeleton` surfaces index-staleness ([#2047](https://github.com/kwad77/pincher/issues/2047)).** A skeleton renders a symbol's signature from already-indexed `db.Symbol` fields with **no file read**, so a source edit that drifted the signature without a reindex was previously served silently as the *old* shape — `warnings`/`warnings_v2` empty, `_meta` carrying no stale marker (`mode=full` already caught this via its byte-offset guard). The skeleton render path now runs a **cheap `os.Stat`** (a stat is not a file read — the no-file-read fast path and the #2043 perf win are preserved, and the "renders after delete" property still holds): every skeleton stamps `_meta.rendered_from="index"` + `_meta.disk_verified=false` so a same-size or grown edit is never presented as byte-current, and when the stat proves drift (file gone, or `EndByte` past the current file size) the response carries a `warnings_v2` `skeleton_index_stale` advisory + a re-index `next_step` (mirroring the `mode=full` `stale_byte_offset` shape). The complete same-size/grown-edit catch needs the indexed source **mtime** on the `files` table (the #2043 follow-up) → a stat mtime-compare would then detect all drift; this PR ships the cheap stat-gate + honesty marker. The gate is wired on **all four** skeleton-serving paths — `symbol`, `context` (full + lite), and `symbols` (batch) — not just the single-symbol path: `context` runs the full per-symbol stat-gate, and the `symbols` batch carries a call-wide `rendered_from="index"`/`disk_verified=false` marker (per-entry statting is deliberately skipped on the zero-disk-touch batch path; re-fetch a specific id with `mode=full` for byte-current bytes). `mode=full`/omitted unchanged.
