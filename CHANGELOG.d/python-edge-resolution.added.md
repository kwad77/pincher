**Python cross-file CALLS resolution: one-hop instance-type inference + unique-suffix fallback.** Two layered fixes for Python call graphs that previously stopped at same-file edges. (1) Extractor (`python_extract.py`, both one-shot and `--daemon` paths): simple assignments `x = ClassName(...)` are tracked at function-body and module level (plain `Name` targets only, last assignment wins, rebinding to anything non-class clears the inference — no flow analysis), and a subsequent `x.method()` is rewritten to `<resolved class path>.method` instead of the unresolvable raw attribute chain. A name counts as a class when it's a module-level class in the same file or an imported name whose final segment is capitalized (PEP 8). Inferred edges carry confidence **0.6** — below the 0.7 of statically-written call paths — so consumers can distinguish them. (2) Resolver (`resolveCalls`): when no source-root candidate matches a dotted Python `to_name` exactly, a deterministic suffix fallback accepts the project symbol whose qualified name ends with `"." + to_name` (bridging missing `src.`-style prefixes and imports anchored below the real package root) — **only when exactly one** distinct QN matches; 2+ candidates stay unresolved, never guessed. Scoped to Python edges; Go/JS resolution untouched. A synthesized `@external/` Module phantom (from an unresolved IMPORTS edge of the same path) no longer outranks a real in-project symbol the suffix fallback can find. Measured on a real FastAPI-style src-layout corpus (227 files, 1967 Python symbols): Python→Python CALLS edges **1688 → 2071 (+23%)**, cross-file Python CALLS **829 → 1191 (+44%)**, of which 226 are 0.6-confidence inferred instance-method edges and 157 are suffix-fallback resolutions.
