**`loop` tool — durable work-state for multi-iteration agent loops (loop-substrate PR-8/9; schema v40).** The loop's biggest cost is that its working state (claims, decisions, reopen triggers, "where was I") lives in the transcript, which dies with the context window. The new append-only ledger moves it into pincher: `loop start` opens a named loop; `loop checkpoint` records one iteration's `{claim, decision, confidence, reopen_trigger, evidence}` stamped with the index watermark; `loop list` enumerates; `loop resume` composes ONE bounded brief (default ~800 tokens, `max_tokens` to adjust; oldest checkpoints drop first with `omitted_checkpoints` reporting the cut) containing the checkpoint tail, all open reopen-triggers, the project's ADR keys, and `index_changed_since_last_checkpoint` — with `warnings_v2 code=index_moved_since_checkpoint` when the symbol graph moved under the loop's feet. A fresh session, or a different model, picks up mid-flight work in a single call. ADR remains the home for conventions; the ledger is for in-flight work. Migration v39→v40 (new `loop_checkpoints` table, non-invalidating).
