**Swift extraction promoted to AST tier (1.0) via real tree-sitter (ADR-0008, Phase 2).** Swift `.swift` files now extract through real upstream tree-sitter compiled to WASM (`wazero`, pure-Go / `CGO_ENABLED=0`), behind the per-file all-or-nothing dispatcher; `PINCHER_DISABLE_SWIFT_AST=1` reverts to the regex tier. struct/class/actor → Class, `protocol` → Interface, `enum` → Enum, and `extension Type { … }` is a scope-only container (its methods parent to the extended type, matching the regex `scopeRE`; no separate symbol). func/init → Method (inside a type) or Function (top level); QNs are keyed on `moduleQN` with the `.` separator. `import` declarations emit IMPORTS (net-new — the Swift regex tier had no import pattern). Measured on Alamofire (43 files): **4.7% parse errors** (2 files gracefully fall back to regex — Swift's community grammar is slightly less mature; never worse than before), types near-exact, identical total callable count, **+52 net-new IMPORTS**, richer CALLS (1600→2134). The lower raw symbol-agreement is tree-sitter correctly reclassifying methods the scope-blind regex tier mis-emitted as top-level functions. Validated by inline unit + no-leak (3000 reuses) + fuzz; full `internal/ast` suite green; no corpus golden change (no `.swift` in fixtures). Cost: binary +~3 MB (Swift's grammar is large; wasm 11.2→14.1 MB). **Breaking note:** re-indexing a Swift project changes some symbol IDs where tree-sitter scopes more precisely than the old regex tier.
