**Database self-maintenance: `auto_vacuum=INCREMENTAL` for new DBs + cheap freelist reclaim + WAL/freelist observability ([#2055](https://github.com/kwad77/pincher/issues/2055)).** Freshly-created pincher databases now come up with `auto_vacuum=INCREMENTAL` (set before the schema's first table, applied via the instant empty-DB `VACUUM`) instead of the SQLite default `NONE` that let freed pages from re-index churn bloat the file behind a full exclusive-lock `VACUUM` — measured multi-GB dead space across live stores. A new `IncrementalVacuum()` (`PRAGMA incremental_vacuum`) reclaims those freelist pages with no exclusive lock and is wired into the indexer's quiet maintenance tail alongside `CheckpointTruncate`; it is a silent no-op on legacy `NONE`/`FULL` databases. `health` and `doctor` gain a `db_maintenance` block reporting `page_count`, `freelist_count`, `freelist_pct`, `auto_vacuum` mode, WAL file size, and `high_bloat` / `wal_near_cap` advisory flags so freelist bloat and WAL high-water are visible before they bite. Existing live databases are never auto-VACUUMed — that remains a deliberate operator action.
