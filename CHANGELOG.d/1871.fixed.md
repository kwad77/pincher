**Install-validation harness** now triggers on `workflow_run` keyed to the Release workflow's completion (not the `release: published` event) so it waits for every artifact path — including the long-running Docker image push — to finish before validating. The v0.92.0 release tripped 6/8 install-validation cells on a race the harness couldn't see: direct-tarball cells 404'd on release-asset CDN propagation that hadn't completed by the time `release: published` fired, and docker cells got `manifest unknown` because the docker push job runs ~8 min after the rest of the release workflow. Re-running the workflow against the same tag a day later passed cleanly. Workflow-run triggering removes both races with one change; `workflow_dispatch` for manual retries against past tags is unchanged.
