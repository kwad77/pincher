`symbol`, `symbols`, and `context` accept a new `detail` arg (`"full"` default | `"skeleton"`): skeleton mode replaces each `source` payload with a deterministic structural outline — signature + top-level control-flow lines kept verbatim, other runs elided as `… N lines (calls: A, B)` markers with call names harvested from the symbol's outbound CALLS edges (every edge-listed callee is guaranteed to appear). A representative 120-line mixed-flow function compresses to under 25% of its full-source tokens — shape-not-body reads for the orientation/probe phase. Responses are marked `_meta.skeleton: true` (one top-level marker); `tokens_saved` keeps the honest file-read baseline. In `context`, skeleton mode bypasses the #655 diff cache (cache operates on `detail=full` only, so representations can't poison each other). v1 is a language-agnostic line classifier over the byte-offset-read source; tree-sitter-precise skeletons are the documented v2 path
