**Java extraction promoted to AST tier (1.0) via real tree-sitter ([#1958](https://github.com/kwad77/pincher/issues/1958), ADR-0008).** Java `.java` files now extract through real upstream tree-sitter compiled to WASM (run by `wazero`, pure-Go / `CGO_ENABLED=0`) instead of the regex tier — the second non-Go/Py/JS language at AST tier, after Rust (#1957). Same per-file all-or-nothing dispatcher: a clean parse (`HasError()==false`) yields AST-exact symbols at confidence **1.0**; any parse error or `PINCHER_DISABLE_JAVA_AST=1` falls back to the regex tier (0.85) — graceful degradation. Measured **0% parse errors across 210 real gson files**; IMPORTS match the regex tier exactly, and tree-sitter additionally captures what the scope-blind regex tier misses: **constructors**, **nested/inner classes** (the regex `^`-anchored `classRE` can't match indented `private static class`), real methods with multi-line/generic signatures, and it drops regex false positives (`new XxxException(...)` call sites the regex `funcRE` misfired as methods). Symbol QNs/IDs follow the `moduleQN` "." convention to match the regex tier where shapes coincide; thread-safe across the concurrent indexer via a bounded (≤4) instance pool sharing the Rust pool cap. Validated by an inline unit test (QN/Parent parity, record→Class, imports, calls), a no-leak-under-3000-reuses RSS test (stays flat), and a marshaler fuzz target (196k+ execs, no panic). Binary size +~0.4 MB (java grammar in `ts.wasm`, 1.17→1.58 MB). **Breaking note:** re-indexing a Java project changes some symbol IDs where tree-sitter scopes more precisely (nested types, constructors) than the old regex tier — announced, not silent.
