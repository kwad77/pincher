**`TestUpdateCLI_CheckBinary` is hermetic against git-fetch credential flake (#1875).** The test exercises `pincher update --check`'s in-repo-mode dispatcher by building the binary + invoking it from inside the checkout; the in-repo path then runs `git fetch origin` to compute ahead/behind. CI runners using `actions/checkout@v4` normally have an `http.extraheader` credential set on the repo so the subprocess fetch authenticates without prompting, but on some PR-CI runs the helper doesn't fire on the subprocess and git falls through to a TTY prompt → "could not read Username for 'https://github.com'" → exit 128 → test fails on what is functionally a network-auth flake. Caught on PR #1873's Coverage gate. The fix probes `git fetch --dry-run origin` up-front and `t.Skipf` if the probe fails — the test's documented contract is "dispatch + in-repo detection works", which doesn't need a real fetch to verify.
