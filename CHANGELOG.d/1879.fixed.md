**`onboard_module` annotates empty `entry_points_local_to_scope` instead of silently returning `[]` (#1879).** Pre-fix, scoping the composite to a library package (no `main()` / `Test*()` / `init()`) returned an empty entry-points list with no explanation — a new contributor reading the response couldn't tell whether the package had no entry points, the heuristic skipped them, or pincher was broken. The fix emits a `warnings_v2.no_entry_points_in_scope` entry explaining the criterion (`is_entry_point` fires only for main/Test/init) and adds a `next_steps` hint pointing at the most-consumed exported symbol (the actual "where do I start reading" answer — the public API surface called from outside the directory, computed from the existing `external_consumers` list). No SQL or extractor changes; pure response-envelope improvement.
