`pincher doctor --fix` now reaps orphaned project locks ([#1860](https://github.com/kwad77/pincher/issues/1860)). A pincher process can outlive its purpose — a detached `--http` server from a closed session, a dev build superseded by `make install`, an MCP child whose client disconnected — and sit there holding a project lockfile so the next pincher hits `project already being indexed`. `doctor --fix` now reclaims stale lockfiles whose holder is dead or whose PID was recycled by an unrelated process (verified by cross-platform executable identity — pure file removal, no process touched). Live version-skewed orphan pincher processes are reported with an escalation hint; the new `--reap-orphans` flag opts in to terminating them, gated behind four checks so a legitimate same-version concurrent indexer is never killed.
