**`.pincherignore` — user-controlled ignore file with gitignore semantics.** Place a `.pincherignore` at the project root (or any subdirectory; nested files apply to their subtree) and the indexer excludes matching files from the walk entirely — full gitignore syntax including `#` comments, `dir/` patterns, `*` globs, leading-`/` anchoring, and `!` negation. Motivation (measured): a real project's `data/*.json` model artifacts (2.5 MB each — under the 4 MB per-file cap, so the size gate never fired) became **27,672 junk Setting symbols, 96% of the project**, with no user-facing way to exclude them. Symbols of newly-ignored files are garbage-collected automatically on the next ordinary re-index (they never enter the seen-files bookkeeping, so the #326 tail-pass GC reaps them). `pincher init`'s language census honors the same file, `doctor` gains a `settings_flood` advisory (Setting symbols > 80% of a project's > 1000 total) recommending `.pincherignore`, and the `all_files_blocked` empty-reason diagnosis now names an over-broad ignore file as a possible cause. Note: ignored files are not counted on `IndexResult` — filtering happens inside the walker before files are yielded; the `pincher.index.gc.summary` log line (`files_reaped=N`) is the observable signal when a new rule takes effect.
