**MCP `tools/list` default reverted to the full toolset ([#2054](https://github.com/kwad77/pincher/issues/2054)).** `PINCHER_TOOLSET` now defaults to `full` (every registered tool advertised) instead of the v1.6 `core` set, while `PINCHER_SCHEMA_STYLE` keeps defaulting to `lean`. The `core` default omitted bootstrap- and diagnose-essential tools (`index`, `init`, `health`, `architecture`, `doctor`, `adr`, `context_for_task`, `plan_change`, `investigate_failure`, `why_empty`), so a fresh MCP client could neither index nor diagnose a project from `tools/list` alone. The measured token win was always dominated by the schema-style lever, not the toolset lever: full/lean is ≈ 7.1k `tools/list` tokens (vs ≈ 19k full/rich — the lean transform captures ~12k), and narrowing to core/lean (≈ 3.3k) saves only a further ~3.7k — not worth breaking onboarding. Set `PINCHER_TOOLSET=core` (or `--toolset core`) to re-narrow the advertisement for token-tight setups; every tool stays reachable over HTTP `POST /v1/<tool>` and the read-only set as `batch` sub-queries in both modes, and under `core` the `guide` recommendations that name a non-core tool still carry the `PINCHER_TOOLSET=full` escape-hatch note.
