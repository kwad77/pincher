## Q1 — POST /api/v1/orders business logic

**orders.ProcessOrder** in `internal/orders/process.go`. Full hop chain:

1. Route registered in `internal/api/server.go` (`NewServer`) → `(*Server).handleCreateOrder` (`internal/api/handlers.go`).
2. `handleCreateOrder` calls `dispatch.Dispatch(ctx, "order.process", body)` (`internal/dispatch/registry.go`) — string-keyed indirection, no direct call.
3. The binding is created in `internal/orders/register.go` `init()`: `dispatch.Register("order.process", processAction)`.
4. `processAction` unmarshals and calls **`ProcessOrder`** (`internal/orders/process.go`), which validates, captures payment, persists, enqueues.

Credit requires: handleCreateOrder + the dispatch/registry indirection (action name
`"order.process"` or the register.go init) + orders.ProcessOrder as the endpoint.

## Q3 — is ProcessOrderV1 dead?

**Dead.** No callers, no `dispatch.Register` of it, not referenced from any cmd/,
non-test or otherwise. (Pincher: 0 inbound edges.) The only textual occurrences are
its own definition in `internal/orders/process_v1.go`. Note: `"process_order_v1"`
inside it is a queue job-type string, not a caller.

## Q4 — can workers/handlers/legacy.py process_order run?

**No — it is never registered.** Handlers enter `lib.registry.HANDLERS` only via the
`@register("job_type")` decorator at import time; `workers/handlers/__init__.py`
imports only `inventory_handler`, `order_handler`, `refund_handler` and explicitly
NOT `legacy`. `legacy.process_order` has no decorator and its module is never
imported, so `route()` in `worker_main.py` can never resolve to it.

## Q6 — checkout click → which Python function fulfills?

1. `wireCheckout` (`web/src/ui/checkout.ts`) → `dispatch("order/submit")` (`web/src/registry.ts`)

Credit requires the right Python function + at least the connecting string keys
("order/submit" or actions.ts; "order.process"; job type "process_order").

## Q7 — order_retry_limit default

**7, defined in `gen/defaults.gen.json`** (machine-generated by configgen; the same
file is read by both runtimes). Consumed in Go by **`config.OrderRetryLimit()`
(internal/config/config.go), called from `billing.ProcessOrder`
(internal/billing/charge.go)** as the capture retry bound.

Decoys an arm must NOT report as the default: the `return 3` last-ditch fallback in
config.go, the `int(get("order_retry_limit", 3))` fallback in workers/lib/config.py,
and `retry_limit_at_capture` values 3/5 in fixtures/orders_fixture_*.json (historical
snapshots). The bundle's `order_retry_limit:7` is consistent but is not the defining
location. Accept: "7 from gen/defaults.gen.json (env ORDER_RETRY_LIMIT overrides;
falls back to 3 only if the generated file is missing)".
