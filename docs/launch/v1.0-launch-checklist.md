## Day-Of-Tag Checklist

1. Confirm `v1.0.0` tag release workflow is green.
2. Confirm install validation is green.
3. Replace every `<<...>>` slot in the announcement, changelog hero, and
   landing-page copy.
4. Verify install snippets for Homebrew, direct binary, Docker, and Go install.
5. Publish the blog post.
6. Add the blog and demo links to the GitHub release body.
7. Post the Twitter / X thread.
8. Submit the r/golang post.
9. Submit Hacker News and lobste.rs links if the blog is public.
10. Watch issues for upgrade failures for the first 24 hours.

## Claims Policy

- Every numeric claim must link to a methodology document or current workflow
  artifact.
- Do not quote dollar savings.
- Do not compare against named products.
- Be explicit about deferred surfaces: plugin extractors, team/shared indexes,
  and unshipped MCP protocol capabilities.
- Use "local code intelligence for agents" as the default product category.
