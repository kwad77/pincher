## Headline: the default surface reaches its memory, and the routing loop names its own failures

v1.8.0 closed the routing loop around the v1.7 surface. v1.9.0 is the
hardening pass a real dogfood session earned: it gives the **default**
tool surface a reachable cross-session-memory path, and it makes the
v1.8 route-outcome auto-echo *diagnosable* when it doesn't fire. No new
tools, no schema migration — both changes are additive and
detection-conditional, and the frozen v1.0 tool-contract golden plus the
`_meta` envelope are untouched.

## `adr` joins the core toolset (#2031, issue #2020)

On the v1.6 default `PINCHER_TOOLSET=core` advertisement, an MCP-only
client could neither read nor write ADRs. `adr` wasn't advertised, and
the documented escape hatch — `batch` sub-queries — dispatches the
**read-only** sub-tool set only (search, symbol, symbols, context,
trace, query, neighborhood, changes; no writers). Meanwhile the shipped
pincher-loop methodology prescribes `adr list` at Frame and `adr set` at
Capture. A memory tool you can't reach isn't memory.

`adr` now ships in `coreToolset`. The default surface is **11 tools**
(13 with the detected-state router pair). Measured core+lean schema
weight: **3236** approx tokens router-absent (was 3094), **3657**
router-present (was 3515) — both comfortably under the unchanged
**4000**-token budget gate. The full/rich tool-contract golden is
unchanged (core membership doesn't touch it). Pinned end-to-end by
`TestADR_CoreMode_MCPRoundTrip` — a real in-memory MCP session whose
`tools/list` advertises `adr` and whose `set → get → list` round-trips
over `tools/call` with no env opt-out and no HTTP.

Corrected en route: the v1.6.0 changelog wording that claimed `batch`
sub-query dispatch "keeps the full 34-tool surface" overclaimed — it
covers the read-only query set, never write tools.

## Route-outcome auto-echo made observable and join-hardened (#2033, issue #2032)

The v1.8 outcome auto-echo (#2026) caches each `route` consult's
`request_id → echo fields` and auto-completes the dispatch verse's
minimal card `{request_id, outcome_class, gate}` before forwarding to
the router. In production it was observed *not* firing on a live
same-session route→outcome pair: the card forwarded un-echoed and the
router answered 422 `missing session_id` — while the entire #2026 test
family stayed green.

Replaying the exact live transcript payloads through the **real MCP
layer** reproduces a correct echo, so the in-process logic is sound. The
production gap is **environmental**: the request_id → echo LRU is
in-memory and does not survive a process respawn between the two calls.
Auto-restart-on-drift, a crash, or any MCP client reconnect transparently
respawns the stdio server — the caller cannot distinguish that from "same
process". Three changes make the failure name itself:

1. **`echo_source: cache|caller|none`** on every `route action=outcome`
   response — the un-echoed forward now announces itself instead of
   masquerading as the tested happy path.
2. **Loud miss log**: `echo_source=none` (cache miss AND no
   caller-supplied `session_id` — exactly the body a validating router
   422s) emits `pincher.route_outcome.echo_miss` with the request_id.
3. **Join hardening**: request_id extraction is normalized (string or
   JSON number) on both sides of the join via `routerRequestID`, instead
   of a silent `.(string)` assertion that disabled the cache write with
   no trace.

The #2026 honest-422 posture is unchanged: the proxy still never invents
echo values it didn't see. Pinned by the `TestIssue2032_*` family,
including a real-MCP-session replay of the live unit-10 transcript.

## Upgrade notes

- No schema changes to the frozen v1.0 tool surface; everything is
  additive. `adr` joining core is purely additive — clients pinning a
  specific toolset see no removal.
- The route-outcome change is observability-only on top of #2026 — no
  behaviour change to a card that already echoed; `PINCHER_ROUTER=off`
  remains the one-knob rollback for the entire routing integration.
- An older router still works: the proxy's honest-422 posture is
  preserved, and a cold-cache miss now surfaces loudly rather than
  silently.
