## Headline: routing, end to end

v1.7.0 shipped the routing-*ready* surface — detection ladder, `router`
capability tag, conditional `models`/`route` proxies, `init --router`
seeding, the dispatch verse. v1.8.0 closes the loop around it: the
recruitment advisory, the outcome auto-echo, the dashboard Models tab,
and the user-facing routing guide. If the SHIP gate passes, this is the
release where routing graduates from dev-channel to a GA claim:

> `[GATE]` Over N routed Make-stage task units in dogfood + bench:
> X% routed below the originating tier, S5 pass-rate within 1 catch of
> the all-originating arm, $/iteration Y% below frontier-only.
> *(Numbers land here only when measured; delete this block otherwise.)*

The safety argument behind cheap-worker routing is already measured and
shipped in the verse: maker/checker family, n=30/arm — the
originating-tier gate caught **30/30** seeded defects in every arm. The
gate never routes below the originating tier; a cheap maker's wrong
answer costs one retry, never a shipped defect.

## The one-time recruitment advisory (#2025)

Sessions that spawn subagents without ever consulting a detected router
now get exactly one non-blocking PreToolUse hint pointing at the
dispatch verse. The design follows the measured hook lesson (726 live
invocations, 0 redirects, 725/726 unindexed paths — hooks excel at
recruitment advisories, not in-band decisions): trigger on the 3rd
`Task` spawn of a session, once per session, `continue: true` on every
branch, no network inside the <50 ms hook budget. Take-rate is
instrumented (advisory → route-consult conversion), not asserted —
`[GATE]` insert measured take-rate when the telemetry has enough
sessions.

## The outcome auto-echo (#2026)

Reporting outcomes is what trains the router, and the biggest reporting
tax was re-assembling the echo fields. The `route` proxy now caches each
route call it forwards and auto-fills the OutcomeBody echo (session,
tool, complexity tier, role, tokens, routed model, lane) from the cached
call with the same `request_id` — the minimal card
`{request_id, outcome_class, gate}` is now a complete report. Explicit
fields always win; cache misses pass the card through unchanged.

## The dashboard Models tab

`pincher web` gains a **Models** tab — rendered only when a live router
was detected at startup, the same conditional-surface discipline as the
MCP advertisement. No router ⇒ no tab, no fetch, and the dashboard HTML
is byte-identical to a router-less build (the absent-state snapshot
fixtures were not regenerated for this change; their byte-identity is
the assertion).

Per worker: kind, tier, enabled state + `enabled_by` provenance, raw
cost spec (null = free-by-construction; no model-price guesses),
`last_seen` freshness against the 24 h ghost-worker bar, source
(declared/discovered), and a win-rate placeholder that stays "—" until
the router exposes per-worker outcome stats. The contract-v2 handshake
renders as chips. The tab is **read-only by design** — the router owns
all registry state; nothing in pincher can enable a paid worker (the
governance line).

## Upgrade notes

- No schema changes to the frozen v1.0 tool surface; everything is
  additive and router-gated.
- `PINCHER_ROUTER=off` remains the one-knob rollback for the entire
  routing integration — no probes, no proxy calls, byte-identical
  advertisement.
- Routers older than contract v2 keep working: installed-but-old
  renders with an upgrade hint, never a vanished surface.
