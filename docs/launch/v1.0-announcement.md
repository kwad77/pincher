## Working Title

Pincher 1.0: local code intelligence for agent workflows

## Draft

Pincher is a local code-intelligence server for coding agents. It indexes a
repository into symbols, relationships, source byte ranges, and search corpora
so an agent can ask targeted questions before reading whole files.

The 1.0 release is about stability. Pincher's MCP tool surface, CLI install
paths, schema migration path, diagnostic commands, and host setup docs have
been through the final RC cycle. The compatibility promise is written down in
the v1.0 frozen-surface ADR, and future changes follow semantic versioning:
additive work lands in 1.x, breaking changes wait for 2.0.

The core workflow is intentionally small:

1. Install the binary.
2. Run `pincher setup` or `pincher init` for your host.
3. Index a repository.
4. Let your agent call `search`, `context`, `trace`, and the composite tools
   before it falls back to broad file reads.

Pincher is not a hosted code-search product and it is not a team index. The
v1.0 boundary is a single-user local SQLite store, a local MCP server, and
documented host integrations. That boundary is deliberate: it keeps setup
simple, keeps source on the developer's machine, and makes failures inspectable
with `pincher doctor`, `pincher stats`, and the HTTP dashboard.

The graph underneath the tool surface has three layers:

- byte-offset source lookup for exact symbol reads;
- FTS5 search corpora for code, config, and documentation;
- project-scoped symbol and edge tables for call, import, reference, and
  structural relationships.

That model lets the agent answer practical questions in one or two calls:

- "Where is this function defined?"
- "What code calls it?"
- "What imports and callees should I read before editing it?"
- "Which files are likely involved in this test failure?"
- "What is the public surface of this module?"

Several things are intentionally not in 1.0. The plugin extractor surface is
deferred to 1.x. Shared team indexes and a server-backed SQL store are deferred.
MCP resources, completions, and visual tool icons are tracked for later
versions rather than being frozen prematurely. The goal for 1.0 is a stable
local tool contract, not the largest possible surface.

For upgrades from older versions, use the migration guide. Pincher runs
forward-only SQLite migrations on open; patch releases in the RC line fixed the
upgrade paths that dogfood exposed, including stale read-only CLI opens and
interrupted index recovery. If something looks wrong after an upgrade, run
`pincher doctor` first; it reports schema version, stale project indexes,
recent extraction failures, slow queries, and store-level advisories.

For new installs, start with the host tutorial that matches your editor:
Claude Code, Cursor, VS Code Copilot Chat, Codex, JetBrains, Zed, or the HTTP
dashboard. The same Pincher binary serves all of them.
