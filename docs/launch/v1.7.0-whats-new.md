> #2018, #2019, #2021, #2023 (issues #2011, #2012, #2014, #2020).
> Every number cited is measured, per the project's

## Headline 1: fresh indexing is 5.0× faster (2,177s → 437s at k8s scale)

A fresh index of a 17k-file corpus spent **~85-90% of its 36 minutes**
in one query: the per-file cross-file-referrer lookup, running against
a SQLite database with **no query-planner statistics** (`ANALYZE` only
ever ran at open on an *empty* DB — which produces no stat rows), so
the planner degraded a three-index-seek query into a full edges-index
scan per file: O(files × edges), measured 101µs → 261ms per call on a
78k-edge table (#2012).

Two fixes (#2018):

- the lookup is **skipped when its result is statically known to be
  empty** — force/full reindexes, and files with no previously-indexed
  symbols, i.e. every file of a first-ever index;
- `Index()` now **guarantees real `sqlite_stat1` rows at completion**
  (probe + one-time `ANALYZE`, cached per store), so incremental and
  watcher runs always plan sanely.

Fixed en route: ambiguous bare-name binding edges (`binding_pass`,
confidence 0.4) used to bind to whichever same-named candidate
happened to flush first — a timing artifact. Candidates are now
ordered deterministically (lexicographically smallest symbol ID,
#428-canonical), so the same tree indexes to the same edge set every
run. Re-verified in release prep on the pincher corpus: identical
symbol and edge counts vs a v1.6.0-binary index, bit-identical edge
sets across repeated runs, and the only cross-version delta is the
documented ambiguous-binding class (81 of 18,799 edges). Persist-path
batching — the next bottleneck — is tracked in #2017.

## Headline 2: the routing-ready surface (and what it costs when you don't route: nothing)

pincher can now act as the **rendering end of an external routing
service** — a local "router" that decides which model/tier should run
a task unit. The design rule throughout: *the surface does not exist
until a real router does.*

- **Detection ladder (#2019).** Once at server start, cheap → expensive:
  config-dir stat → router binary on `$PATH` → an identity-validated
  `GET /healthz` (200 + JSON body carrying `weights_version`;
  redirects not followed). Identity validation is mandatory — both
  real-world false positives from the spike (a pincher HTTP instance
  answering on the router's port; a 302-redirecting dashboard) are
  replayed as rejection fixtures. Bounded at 50ms; zero network
  traffic when nothing is installed; every failure mode is "absent".
  Detected ⇒ a `router` tag in `_meta.capabilities` and
  `GET /v1/capabilities`.

- **Two thin proxy tools (#2021).** `models` renders the router's
  registry plus the version-skew handshake
  (`{contract_version, weights_version, registry_version,
  capabilities}`); `route` consults the router before a task unit
  spawns (mode-tagged response: `execute` = gate the worker's output
  as untrusted input, `advise` = spawn a host subagent at the advised
  tier) and reports gated outcomes back — the loop trains the router
  as a side effect of working. pincher renders, the router owns
  state; pincher **never** writes the router's registry.

- **Surface discipline.** Both tools are always registered (HTTP
  `/v1/models`, `/v1/route`, OpenAPI, tool-contract golden = the full
  36-tool surface), but they are **MCP-advertised only when a live
  router was detected** — in which case they join the core set
  (core+lean: 3,094 → 3,515 approx tokens, still under the same
  4,000 budget gate). Router absent ⇒ the advertisement is
  **byte-identical to v1.6.0** (verified live against the installed
  v1.6.0 binary in release prep, both toolset modes).

- **Never-block semantics.** Every proxy call is bounded at 250ms.
  Unreachable, hanging, non-JSON, or erroring routers return a
  structured error telling the loop to proceed at the originating
  model and checkpoint the miss — re-verified live in release prep
  against fixture routers in all four failure modes. Pre-v2 routers
  degrade gracefully (untagged plans treated as `execute` with a
  warning; old handshakes render with an upgrade hint).
  `PINCHER_ROUTER=off` is the rollback story: zero probes, zero proxy
  dials, surface identical to no-router (also verified live: zero
  fixture dials with a live router installed and configured).

- **Seeding (#2023).** Opt-in `pincher init --router` runs the same
  detection ladder from the CLI, prints per-rung status, refreshes a
  short routing subsection inside the existing CLAUDE.md managed
  block (idempotent; refreshed back out by a plain re-init), and
  installs the dispatch-verse-carrying pincher-loop skill (v0.4.0).
  No router detected ⇒ the flag errors with install guidance and
  **writes nothing** — the routing block can never lie.

## The hook recruits the index (#2016 / #2014)

A live audit of 726 hook invocations across 110 sessions found the
PreToolUse hook at a **100% pass-through rate**: virtually every
intercepted event targeted files outside every indexed root — the
redirect machinery had no index to redirect to. Now, when a session
Reads code files 3+ times inside a git repo pincher has never indexed,
the hook emits a **one-time advisory** recommending
`pincher index <root>`. Guardrails: once per root per session, never
for non-repo trees, never for $HOME / filesystem root / temp dirs
(the shared bloat-trap guard), and always advisory — the Read passes
through. Take-rate is measurable (advisory rows join against
`projects.path`).

## Glob advisory is toolset-aware (#2013 / #2011 — v1.6.0's recorded sev-2, closed)

v1.6.0's release review recorded one sev-2: the new Glob advisory
recommended `onboard_module`, which a default core-toolset session
cannot `tools/call` (-32602). The advisory now resolves its
recommendation against the active toolset: core sessions get `search`
(advertised in both modes) plus the two real escape hatches (`batch`
sub-query, `PINCHER_TOOLSET=full`); full sessions keep the original
`onboard_module` recommendation. The divergence case (hook env ≠
server env) is safe by construction — the fallback is callable in
both modes.

## Compatibility

- Registered tools 34 → **36** (`models`, `route`) — additive only;
  zero changes to the existing 34 (verified live: byte-identical
  `tools/list` entries vs the v1.6.0 binary).
- Default advertisement stays **10** tools (**12** with a router
  detected).
- Schema stays **v41** — zero migrations in the window.
- No tool, field, `_meta` key, HTTP route, CLI subcommand, or
  symbol-ID format removed or renamed (ADR-0002). MINOR bump.
