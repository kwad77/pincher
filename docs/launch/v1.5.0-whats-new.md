# pincher v1.5.0 — What's New (draft for the GH release; dev channel)

## The self-measuring loop

v1.4 made pincher a substrate for long-running agent loops. v1.5 closes
that loop: the substrate now **measures itself** (LES), **hands itself
off** (pointer manifests), **survives compaction** (the PreCompact
hook), and **benchmarks itself reproducibly** (loopbench). No new
tools, no schema change — the tool count stays 34 and the schema stays
v41; everything below is additive against v1.4.0. Every number cited
is measured, per the project's no-invented-numbers rule.

### LES — the Loop Efficiency Score (#1999)

Pincher's own success metric, computed entirely from telemetry it
already records — free local compute, conclusions-only surfacing:

- **iteration_cost** — recorded tokens ÷ non-empty-decision loop
  checkpoints (empty decisions never count, per ADR
  `LOOP_EFFICIENCY_METRIC`'s anti-gaming rule).
- **waste_rate** — unexpected-empty queries + error envelopes +
  budget-truncated responses + ignored hook redirects, over total calls.
- **recovery_load** — plan_stale / unpredicted_impact / index-drift
  warnings + `investigate_failure` calls.
- **continuation_fidelity** — sessions that open from the loop ledger,
  over sessions on a ledger-bearing install.

Surfaces: one compact LES line in `stats` for this session and one for
the trailing 7 days; a priced `les_regression` finding in `coach` when
a sub-metric moved week-over-week (basis strings show the exact
arithmetic); a one-line `les_hint` on `loop resume`. Honesty is the
contract: inputs that aren't recorded render `-` — the 7d window's
error-envelope and warning-code counts aren't persisted, so the basis
strings document the omission rather than faking a number, and the
diff-context hit ratio the ADR mentions is named as unrecorded, not
invented. 13 new tests pin the arithmetic exactly. LES is diagnostic,
never a per-call gate — stated in the coach basis itself.

### Pointer handoffs: `loop handoff` + `loop export` (#1997)

Prose handoffs cost 2–5k tokens to compile, rot instantly (line drift
measured within 3 iterations), and charge the next session the full
re-read. `loop action=handoff` composes the manifest **server-side** —
open reopen-triggers with `AWAITING HUMAN` entries verbatim
(trim-exempt), ADR keys, a real dirty-tree summary via the shared
changes analysis, the current watermark, recent checkpoint receipts,
and re-entry seed ids parsed from checkpoint evidence — and stores it
as a regular checkpoint. **Measured: a full fixture manifest lands at
72 tokens, and the ≤600-token cap holds against a 40-checkpoint ×
480-token ledger.** Writing one costs ~200 tokens vs 2–5k for prose;
resuming costs ~150 — and every pointer dereferences **live** state
instead of freezing line numbers. `resume` now leads the brief with
the newest handoff (pinned by test). `loop action=export` renders
human-readable Markdown FROM the ledger on demand, windowed since the
previous handoff — prose only when someone actually needs it, never
written to disk.

### PreCompact: ledger-aware compaction advisories (#1998)

The symbolization→window-shrink law, harness-side: when Claude Code
compacts a long session, facts already checkpointed in the ledger can
drop to pointers — but only if the summarizer knows. `pincher
hook-check` now handles PreCompact events: cwd→project resolution
(same fail-open posture as the PreToolUse path), a **≤3-read ledger
probe** (structurally enforced by a 3-method store interface + a
counting-decorator test), and a dual-channel advisory (`systemMessage`
+ `hookSpecificOutput.additionalContext`): *"Durable state lives in
pincher: loop X (N checkpoints, latest receipt), M open triggers, K
ADRs — prefer pointers over payload reproduction; recoverable via loop
resume / adr get."* Empty ledger → silent passthrough; malformed
events → bare continue; the handler never blocks. `pincher init
--target=claude` registers the PreCompact leg additively and
idempotently beside PreToolUse — legacy installs gain it on re-init.
Telemetry rides existing `hook_invocations` columns
(`tool_name="compact"`): no schema change. 13 new tests.

### loopbench: reproducible cross-toolset benchmarks (#1996)

`scripts/loopbench/` replaces ad-hoc benchmark agents with
reproducible `claude -p` arms: five arm specs (native-naive,
native-coached, pincher-mcp over **real stdio MCP**,
pincher-mcp-coached with the phase-aware policy, and the deprecated
curl arm for comparison), the standard 5-question task set plus a
12-question graph suite with symbols verified at a pinned commit, and
a TSV scoreboard with billing-grade usage capture. **Proven
end-to-end: the native smoke answers correctly at 52.3k total tokens;
the stdio-MCP smoke calls `health` through the real transport and
reports the schema.** The usage-JSON shape of claude CLI 2.1.173 is
recorded verbatim in the README. Findings worth keeping (documented in
the README): the CLI's variadic `--allowedTools` swallows a trailing
prompt argument (worked around via comma-joined lists + a stdin
prompt), and pincher arms can inject the init-managed CLAUDE.md block
into the repo under test — check `git status` after runs.

### The fine print

- Tool surface: 34 tools before, 34 after. The `loop` tool gains the
  `handoff` and `export` actions, `note` and `seq` args, and the
  `les_hint` resume field — all additive, golden-file verified.
- Schema: v41, zero migrations.
- Review: frozen-surface review vs v1.4.0 passed clean (all six
  contract gates green); adversarial review found **0 sev-1**; the
  sev-2/sev-3 notes (including a cross-PR LES×handoff metric skew) are
  recorded in `docs/release-signoff-v1.5.0.md`.
