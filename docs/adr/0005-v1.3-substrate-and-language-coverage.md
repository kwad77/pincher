## Context

v1.0 froze the public surface. v1.1 stabilized the post-1.0 backlog. v1.2 turned existing indexed evidence into reportable artifacts without changing Pincher's substrate identity.

The next minor needs to **prepare the substrate** for capabilities that don't fit Pincher's current shape — specifically:

- inferred / heuristic / LLM-derived edges (community clustering, semantic edges, plugin-emitted edges) that ADR-0004 deliberately deferred until they could be made **separable** from deterministic extraction;
- language-tier coverage that requires AST-level work outside Go (Rust, Java, Swift) plus a coherent policy on how non-Go ASTs are obtained — bundled helper, build-on-first-use subprocess, tree-sitter+CGo;
- the long-deferred MCP protocol capabilities (Resources, Prompts, Progress notifications, Completion, Tool icons) whose absence has been masked by Pincher's tools-only surface so far;
- a strategic spike to validate the SCP-aligned envelope hypothesis ([#1397](https://github.com/kwad77/pincher/issues/1397)) without compromising current `_meta` performance.

These items share a property: they are **substrate-shaped**, not feature-shaped. They unlock future work more than they ship visible behavior. Bundling them into v1.3 keeps v1.4+ feature releases honest because the foundations they need exist.

## Decision

**v1.3 will be a substrate + language-coverage + MCP-protocol-completeness release, not a feature release.**

The release should prioritize work that enables the next wave of capabilities without diluting Pincher's identity as a deterministic, source-grounded index:

1. **Provenance-tier separability (substrate)** — `edges.provenance_tier` column landed with a default of `'EXTRACTED'` (currently in flight on `feat/v1.3-provenance-tier-groundwork`). Inferred / heuristic / plugin-emitted edges must declare a non-`EXTRACTED` tier. Tools and HTTP/API responses must let callers filter by tier. Reports must surface tier breakdowns separately. Required precondition for any future inferred-edge work per ADR-0004's non-goal.
2. **Schema Phase 2b** — [#1371](https://github.com/kwad77/pincher/issues/1371) widens PKs/UNIQUEs so multi-branch coexistence is structurally honest, not papered over by per-branch DB copies.
3. ~~**Language coverage Tier 2** — Rust ([#1182](https://github.com/kwad77/pincher/issues/1182)), Java ([#1183](https://github.com/kwad77/pincher/issues/1183)), Swift ([#1452](https://github.com/kwad77/pincher/issues/1452)) AST extractors. Gated by [#1689](https://github.com/kwad77/pincher/issues/1689) (non-Go AST strategy ADR) — bundled helper vs build-on-first-use vs tree-sitter+CGo decision must land first.~~ **Resolved-deferred by [ADR-0006](0006-non-go-ast-strategy.md).** The non-Go AST strategy ADR landed and chose Option D (regex tier sufficient; no non-Go AST work in v1.x) with a documented re-open trigger. The three Tier-2 AST issues close as deferred; the regex tier (0.85) remains the v1.x answer for Rust / Java / Swift. Regex-tier promotions per individual language (e.g. [#1450](https://github.com/kwad77/pincher/issues/1450) Swift) continue per their own milestones and are not affected.
4. **Plugin extractor graduation** — [#1333](https://github.com/kwad77/pincher/issues/1333) surface ships from `experimental` (per ADR-0003) to either `evolving` or an extended experimental window with explicit reasons. Resolution required, not deferred indefinitely.
5. **MCP protocol completeness** — Resources ([#1083](https://github.com/kwad77/pincher/issues/1083)), Prompts ([#1082](https://github.com/kwad77/pincher/issues/1082)), Progress notifications ([#1080](https://github.com/kwad77/pincher/issues/1080)), Completion ([#1084](https://github.com/kwad77/pincher/issues/1084)), Tool icons ([#1079](https://github.com/kwad77/pincher/issues/1079)). All additive on the protocol side per ADR-0002.
6. **Resolver perf depth** — IMPORTS dedupe redesign ([#1642](https://github.com/kwad77/pincher/issues/1642)), QN granularity for overloads/scoped types ([#1701](https://github.com/kwad77/pincher/issues/1701)), parallelize resolves ([#1611](https://github.com/kwad77/pincher/issues/1611) — itself gated on observability).
7. **Strategic spike** — [#1397](https://github.com/kwad77/pincher/issues/1397) SCP-aligned envelope foundation, with explicit hard perf gates against current `_meta` latency and token-savings characteristics.

## Non-goals

- **No inferred / LLM / heuristic edges in v1.3 itself.** The substrate is added; consumption ships in v1.4+. Anything that emits non-`EXTRACTED` edges before tier-aware filtering exists is a defect.
- **No clone-parity work** for any external graph-intelligence product. v1.2's framing carries forward.
- **No tool-surface compression.** Re-platforming tools as MCP Resources is an additive protocol capability, not a surface reduction. The existing tool list per ADR-0002 stays frozen.
- **No graduation of Resource URIs** ([ADR-0002](0002-v1-frozen-surface.md) "experimental for v1.0") without a follow-up ADR documenting at least one external consumer.
- **No `_meta` envelope schema breakage.** v3 (`*_v3`) extension points are additive per ADR-0002; SCP-aligned envelope work in [#1397](https://github.com/kwad77/pincher/issues/1397) must use them, not redefine existing fields.

## Release sequencing

### v1.3.0

Minimum ship cut:
1. Provenance-tier substrate (column + default + per-tier filter + report breakdown) — required.
2. ~~Non-Go AST strategy ADR ([#1689](https://github.com/kwad77/pincher/issues/1689)) landed and at least one language extractor (Rust **or** Java) shipped using the chosen pattern.~~ ADR-0006 landed; Option D (regex tier sufficient) means the language-extractor minimum is dropped from the v1.3.0 ship cut. The substrate items (provenance-tier, schema Phase 2b) carry the v1.3.0 visible-to-users story alongside the MCP capability and plugin-extractor decisions.
3. At least one new MCP capability — Resources ([#1083](https://github.com/kwad77/pincher/issues/1083)) is preferred since it has the largest unblock effect for dashboard / external-host work.
4. Plugin extractor decision recorded — even if the decision is "extend experimental", it must be explicit in ADR.

Everything else moves to v1.3.x patches or v1.4.

### v1.3.x

Trailing slots for the remaining MCP capabilities, additional language extractors, and resolver perf depth.

## Consequences

**Positive:**

- Unblocks v1.4+ capability work (community clustering, plugin-emitted edges, semantic augmentation) that v1.2 explicitly deferred.
- Brings Pincher's MCP surface closer to protocol-complete, removing host-integration friction that has shown up in dogfood (Cursor sign-in gotcha, Codex stdio transport).
- Closes the AST-tier language coverage gap for the three regex-tier languages most often reported in dogfood (Rust, Java, Swift).
- Forces a decision on the plugin-extractor experimental surface that has been deferred for multiple minors.

**Negative:**

- Substrate releases are unsexy. The release notes lead with "structurally honest separability" rather than a visible feature; market-facing framing requires care to avoid sounding like "nothing shipped."
- Tier-2 AST extractors are heavy. Slipping any of the three to v1.3.x is normal; slipping all three would weaken the language-coverage story.
- SCP envelope spike ([#1397](https://github.com/kwad77/pincher/issues/1397)) may surface that the proposed substrate redesign doesn't meet the hard perf gates. If so, the work is shelved and that itself is the v1.3 contribution to the strategic decision.

**Mitigations:**

- Frame v1.3 release notes around concrete unlock outcomes ("Rust users now get the same call graph fidelity as Go", "Hosts can subscribe to indexing progress notifications", "Plugin extractor authors have a stable API to target") rather than substrate vocabulary.
- Pre-commit to at least one second-language-tier extractor in the v1.3.0 ship cut so the release has a visible-to-users element.
- For the SCP spike, treat a negative outcome (perf gates fail) as a successful experiment, not a release defect — document the result in a follow-up ADR.

## Success metrics

- `pincher doctor` and `pincher report` show edge counts broken down by `provenance_tier`. No tool returns mixed-tier results without a `tier=` filter being available.
- A fresh repo in at least one of Rust/Java/Swift produces a snapshot-equivalent extraction count to the current Go corpus (`testdata/corpus/<lang>.snapshot.json`).
- At least one external MCP host has subscribed to `notifications/progress` on a long-running tool call against pincher (dogfood evidence required, not just the test surface).
- Plugin extractor status is unambiguous in ADR — `experimental`, `evolving`, or `frozen` — and the decision is justified in the ADR body with consumer evidence.
- The CHANGELOG `DOGFOOD:` subsection for v1.3 names at least three dogfood findings the substrate work surfaced that would otherwise have been silent.
