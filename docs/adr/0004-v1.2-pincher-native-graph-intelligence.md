# ADR-0004: v1.2 Pincher-native graph intelligence

**Status:** Accepted
**Date:** 2026-06-08
**Decision-maker:** kwad77 (sole maintainer)
**Issues:** [#1911](https://github.com/kwad77/pincher/issues/1911) umbrella; [#1912](https://github.com/kwad77/pincher/issues/1912), [#1913](https://github.com/kwad77/pincher/issues/1913), [#1914](https://github.com/kwad77/pincher/issues/1914), [#1915](https://github.com/kwad77/pincher/issues/1915), [#1916](https://github.com/kwad77/pincher/issues/1916), [#1917](https://github.com/kwad77/pincher/issues/1917), [#1918](https://github.com/kwad77/pincher/issues/1918), [#1919](https://github.com/kwad77/pincher/issues/1919)
**Related:** [#1858](https://github.com/kwad77/pincher/issues/1858) interactive graph view, [#1859](https://github.com/kwad77/pincher/issues/1859) why/rationale nodes

## Context

Recent research into external graph-oriented codebase tools highlighted useful product patterns: persistent architecture artifacts, rationale/design-intent maps, hotspot/community views, surprising connections, and graph exports. Those ideas are valuable, but Pincher should not become a clone or parity chase for any external graph product.

Pincher has its own differentiated substrate:

- deterministic source extraction with file/line/span provenance;
- low-latency MCP, HTTP, and CLI code-intelligence surfaces;
- freshness, schema, binary-version, and stale-index diagnostics;
- `trace`, `changes`, `context_for_task`, and other workflow-native tools;
- `_meta` envelopes carrying latency, complexity tier, token usage, savings, warnings, and capabilities;
- dogfood and pincher-router loops that can turn every call into routing-quality evidence.

The v1.2 opportunity is to package that substrate into higher-leverage outputs without diluting Pincher's identity.

## Decision

**v1.2 will be a Pincher-native graph-intelligence and routing-leverage release, not a Graphify-parity release.**

The release should prioritize features that transform existing Pincher evidence into useful artifacts and routing signals:

1. **Architecture report artifact** — a compact markdown report generated from existing indexed evidence: project metrics, entry points, hotspots, surprising connections, rationale snippets, health/freshness warnings, and suggested next Pincher calls (#1912).
2. **Rationale map** — first-class grouping and querying of design-intent/rationale nodes with source spans, confidence, and attachment status (#1913), building on extractor work in #1859.
3. **Hotspot risk scoring** — explicit graph-aware risk rankings using raw scoring inputs for planning, refactoring, and test prioritization (#1914).
4. **Surprising-connection triage** — deterministic reasons, provenance, and suggested action for unusual package/module edges (#1915).
5. **Falsifiable savings/work-impact report** — raw `_meta` token/latency/baseline fields, formulas, missing-field/schema-gap warnings, and recent-window separation (#1916).
6. **Next-best Pincher calls** — machine-actionable follow-up calls that improve agent execution, next-step adherence, and router-training traces (#1917).
7. **Graph export provenance hardening** — improve `export-graph` as evidence export for external analysis while preserving Pincher's source-grounded identity (#1918).
8. **Positioning/handoff discipline** — keep release language and implementation plans focused on Pincher-native graph intelligence, not clone/parity framing (#1919).

The interactive graph view (#1858) belongs in v1.2 only after the report/rationale/hotspot/savings evidence path exists. The visual surface should display Pincher provenance and routing value; it should not become the primary release driver.

## Non-goals

- No Graphify-parity checklist.
- No default LLM extraction pipeline for v1.2 core features.
- No unsupported marketing claims such as unverifiable fixed multipliers for token savings.
- No dashboard-first implementation that lacks report/API provenance.
- No MCP/tool-surface compression work as a savings track.
- No inferred semantic edges unless they are explicitly marked, source-linked, confidence-scored, and separable from deterministic extracted edges.

## Release sequencing

### v1.1

Keep v1.1 focused on existing post-1.0 backlog, reliability, and extractor foundations. #1859 can land there if it remains focused on deterministic why/rationale extraction.

### v1.2

Use v1.2 for the Pincher-native graph-intelligence bundle:

1. report artifact first;
2. rationale map and hotspot/surprising-edge tools next;
3. savings/work-impact evidence and next-best-call guidance;
4. export/provenance hardening and dashboard visualization only after evidence contracts are stable.

## Consequences

**Positive:**

- Preserves Pincher's product identity and avoids clone optics.
- Produces immediate value for humans and agents using data Pincher already collects.
- Improves pincher-router with falsifiable cost/routing evidence rather than vague savings claims.
- Creates a shippable v1.2 scope with measurable outcomes.

**Negative:**

- Some graph-visualization expectations move behind evidence/report work.
- Community clustering and richer semantic inference may wait for later minors.
- The release requires careful language in docs and release notes to avoid parity framing.

**Mitigations:**

- Keep every issue acceptance criterion tied to raw metrics, source provenance, or `_meta` fields.
- Put the positioning requirement in #1919 and this ADR.
- Treat missing evidence as `missing` or `unsupported`, not a prompt to invent prose.

## Success metrics

- A fresh repo can produce a `PINCHER_REPORT.md` without LLM dependencies.
- Reports include source/provenance for symbol/file claims.
- Savings reports expose raw inputs, formulas, and baseline methods, and refuse unsupported aggregate claims.
- Next-best-call suggestions increase observed follow-through or reduce raw Read/Grep fallback in dogfood sessions.
- Release notes describe Pincher-native graph intelligence and routing leverage, not external-product parity.
